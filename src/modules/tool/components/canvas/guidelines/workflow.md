# 设计工作流（workflow）

> 从需求到出图的端到端流程。核心：**规划 → 构建 → 查看 → 修正（收敛）**。
> 规划越充分，返工越少；查看越勤，最终越精致。

## 标准流程（新作品）

1. **确定用途与画布**：`canvas_create` 按用途选比例与尺寸（见 composition 指南的尺寸表），
   背景色选接近最终的底色（深色海报直接给深色背景，避免后期白底突兀）。
2. **定调色板与字体**：`canvas_set_palette` 定义 3-5 个 token（主色 / 辅色 / 中性色 / 强调色）；
   心中定下标题字体与正文字体（见 typography 指南）。
3. **构建（先骨架后血肉，每批 ≤25 op）**：`canvas_batch_edit` 按「区域分组原则」分批：
   - 批 1：先拆区域，建 group 骨架（背景 / 各区域容器；用内联 `children` 或 `as` 绑定名一批搭好）
   - 批 2：往各 group 里填子元素（文字 / 图形 / 图片；子节点不带 x/y，交 layout 排布）
   - 批 3：装饰细节与跨区域微调（顶层自由坐标 + `ABSOLUTE` 锚点）
4. **查看与校验**：`canvas_export` 导出 PNG，引用返回的 path 查看实际效果。
   - 检查：焦点是否唯一、留白是否够、对齐是否齐、文字是否可读、有无重叠或溢出。
5. **修正（最多 2 轮）**：把发现的问题**合并进一次** `canvas_batch_edit` 修完，再导出复核。
   - ≤4px 的间距噪声忽略；不要无限"再精致一点"。

## 收敛阈值（何时停）

- 每区块最多修正 **2 轮**；第三轮还有问题就记录为已知限制，不再死磕。
- 忽略：≤4px 间距差、装饰元素的微小溢出、子像素偏移。
- 结构正确、符合风格指南后**不要再为了"美感"反复截图**——出货。

## 修改已有作品

1. `canvas_get_nodes` 看当前图层树（拿到 id / 名称 / 尺寸）。
2. 需要精确定位时 `canvas_read` 读 JSON。
3. 用 `canvas_batch_edit` 一次性修：
   - 改某个元素：`update` + path
   - 复制元素改造成变体：`copy` + `overrides`
   - 调整顺序：`move` + `index`（改变 z 序）
4. 导出复核（同收敛阈值）。

## 配色 / 风格不定的情况

- 先 `canvas_guidelines("style-guide")` 与 `canvas_guidelines("composition")` 拿铁律与范式。
- 色彩和谐靠调色板 token 贯穿：所有 fill 用 `$主色`、`$强调色`，不要到处写裸色值。
- 拿不准风格时，选一个明确的视觉方向并贯彻到底，好过"什么都来一点"。

## 图片与素材处理

**真实素材优先**（logo / 品牌图 / 用户指定图片）：

1. **logo**：调用 `website_logo(url)` 工具，按官网地址自动下载真实图标到沙盒 `outputs/images/` 并返回本地路径，把返回的 `path`/`href` 填进 `image` 节点的 `imageUrl`。
2. **其他真实图片**（banner / 配图 / 用户提供的图片地址）：用 `image` 操作 `web` 类型（`url` 填真实地址，自动下载落盘沙盒）；或用 `http_download` 下载后引用本地路径。
3. **图标**：默认用 `svg` 节点，优先 `icon_svg` 工具取真实 SVG（Iconify，免费），返回内联 SVG 字符串填进 `svg` 节点；单色图标可把内部颜色写 `$token名` 跟随调色板。
4. **无真实来源**（照片 / 素材）：才用 `image` 操作 `stock`（picsum 稳定种子）或 `placeholder` 占位。

- **禁止随手编随机图片 URL**；真实素材必须经工具落盘沙盒后使用，禁止自己画近似 logo。
- 图片建议显式 width/height，避免 0 尺寸不可见。

## 交付

- 完成后 `canvas_save`（每次变更已自动落盘，save 兜底）。
- 告知用户画布版本与尺寸，如需导出图片用侧边栏"下载图片"或让用户自行操作。
