# 小红书信息图（生图型）

把用户内容变成可直接发布的 3:4 信息图 / 组图，走**位图直出**路线：`image_generate`（需登录，按张数扣积分）。

固定视觉系统是「**轻盈 AI 产品信息图**」：白色到极浅薰衣草底、黑色大标题、紫蓝与青柠绿强调、圆角白卡、线性科技图标、流程 / 对比 / 清单模块。目标不是复刻某张参考图，而是稳定复用这套系统。

**什么时候用本 skill**：AI / 效率 / 产品 / 财务 / 职场 / 教程 / SOP / 方法论；要单张知识图或 6-9 张连续组图；用户提供参考图，希望借鉴其信息层级与色彩关系；用户就要位图。
**什么时候不用**：要求文字 100% 可编辑、要逐像素改版 → `xhs-cards`（画布，文字用 text 节点排）；要封面单张 → `xhs-cover`；只要正文 / 标题 / 选题 → 对应 skill。

## 默认交付

- 比例竖版 3:4，最终 1080×1440 PNG；一张图只承担一个中心任务
- 数量：明确「单图 / 封面」→ 1 张；说「组图」没给数量 → 给 6/7/8/9 四档并推荐一档；说「你定」→ 短清单 6、完整方法 7、实操教程 8、完整 SOP 9
- 账号名默认只放首页右上角一次（用户没提供就不加），内页不重复
- 每页单独调用一次 `image_generate`，**不要用 `n` 一次出多页**（不同页必须是不同提示词）
- 分辨率档位：试稿用 `resolution: '1k'`，定稿用 `'2k'`（4k 仅印刷级；档位越高积分越贵，开工前可读 `canvas_guidelines("image-generation")` 拿省钱与提示词经验）

## 工作流

### 1. 读内容（先读完再拆页，不要边读边生成）

提取：目标读者、核心承诺（看完能完成什么动作）、最小完整链路（准备 → 操作 → 结果 → 验收）、可直接拿走的材料（步骤 / 提示词 / 字段 / 模板 / 检查表 / 例子）、可删内容（重复铺垫、空泛鼓励、爹味教训）、原文中的具体信息（对象、字段、规则、步骤、数字、阈值、输出名称）。
拆页前建立「**原文依据 → 页面文案**」映射：页面里的具体描述必须能回到原文；为排版可压缩句子，但**不许改造成新口号或泛化观点**。

### 2. 建页序

先输出简短规划（结构 / 数量 / 账号名出现位置 + 每页：页码、页面任务、主标题、原文依据、结构、读者拿走什么），再逐页生成。用户只要单张时不输出规划，直接提炼主标题、重点与结构。

**组图节奏**：
- 6 张：封面 → 结果预览 → 准备 → 核心执行 → 示例或对比 → 验收总结
- 7 张：封面 → 问题与结果 → 准备 → 步骤 1 → 步骤 2-3 → 示例 → 验收总结
- 8 张：封面 → 完整路径 → 输入准备 → 规则与边界 → 第一次执行 → 小样试跑 → 输出与修正 → 验收清单
- 9 张 SOP：封面 → 最终成果 → 输入 → 环境或目录 → 步骤 1/2/3 → 常见错误 → 验收清单

**页面结构库**（按内容选，不连续三页用同一种结构）：
`P1 封面 Hero`（左标签 + 右账号名 + 2-3 行大标题 + 一句副标 + 主图解 + 底部一句结论，45-85 字）｜`P2 结果预览`（看完能完成什么 + 3-4 张并列卡 + 底部最小链路，不做目录）｜`P3 步骤流程`（横向 3-5 节点紫编号细线，或竖向 3-4 卡，每步「动作 + 对象 + 结果/检查」）｜`P4 左右对比`（两张同尺寸大卡，左墨黑 + 浅橙/紫叉，右紫 + 青柠绿勾，中间 VS，两侧句式平行，底部给选择标准）｜`P5 双层拆解`（大圆角容器，上层浅薰衣草「常见理解」、下层浅青绿「更深理解」，底部核心结论）｜`P6 卡片矩阵`（2×2 / 2×3 网格，每卡 1 图标 + 短标题 + 一句 12-28 字说明，同尺寸同基线）｜`P7 输入→处理→输出`（左输入 2-3 项、中处理动作、右可验收输出 2-3 项，下方「验收标准」条带）｜`P8 Before/After`（Before 浅橙/灰紫、After 紫绿，对比维度一致，**不编造节省比例**）｜`P9 操作模板`（顶部要复制什么 + 中部文档/代码感主卡（不做真实软件截图）+ 3 个使用提示 + 底部预期结果；文字多就拆两页）｜`P10 验收清单`（4-6 条勾选，每条「检查对象 + 检查动作 + 通过标准」，底部青柠绿终态）｜`P11 总结收束`（一句结论标题 + 3 个核心动作 + 小闭环图，「收藏后照着做」不夸张催促，不重复目录）

**版式优先关系**：一个结论 → Hero / 单观点；3-5 个步骤 → 流程；A 与 B → 左右对比；3-6 条并列 → 清单 / 卡片矩阵；表层与本质 → 双层拆解；做前与做后 → Before/After；一套完整方法 → 总览 + 分步 + 验收。

### 3. 控制文字（生图模型能写字，但越密越容易错）

**封面**：主标题 8-18 字（最多 2-3 行，可占大面积）+ 副标题 0-28 字；只留主题、结果与一个主视觉，不承担完整教学。
**内页**：主标题 6-16 字（最多 2 行，视觉字号约为封面标题的 55%-68%，标题区高度 8%-14%）；正文 4-6 个模块，每模块「短标题 + 12-28 字完整说明句」（**不能只放名词标签**）；每页 120-180 字（模板页最多 220，但要拆清层级）。
**所有文字逐字写进提示词的 `Text (verbatim)`**，不让模型自行改写。文字过多先拆页；文字不足回原文补字段 / 步骤 / 输出 / 验收要求，不用装饰图标占满空间。

### 4. 文案句式

内页以直接说明为主（「扫描件提取后，需要核对金额、日期和模糊字段」）。**限制口号式句型**：「不是 A，而是 B」「能 A，不等于 B」「不要 A，要 B」「别急着 A，先 B」——除非是用户原文的关键表达，一组图最多用一次。能直接陈述事实就写事实。

### 5. 生成（每页一次调用）

提示词结构（`image_generate` 的 prompt）：

```text
制作一张 3:4 竖版小红书信息图，第 {页码}/{总页数} 页；不增删、不改写给定文字。

【视觉系统 Style Lock】{逐字复用下方 Style Lock 英文段}

【本页构图】{选中的页面结构 + 模块数量 + 位置}
【原文依据】“{对应原句或要点}”——允许压缩，不允许新增结论
【Text (verbatim)】
- 顶部标签：“{标签}”
- 主标题：“{主标题}”
- 副标题：“{副标题}”
- 模块 1：“{文字}” ／ 模块 2：“{文字}” …
【约束】3:4；简体中文逐字准确；外边距充足；信息层级清晰；手机信息流尺寸下主标题仍清楚
```

**系列图一致性**：每页都逐字复用同一段 Style Lock，只换本页标题 / 内容模块 / 图标 / 版式；需要更强的连贯性时，把**上一张已通过的定稿**路径填进 `referenceImagePaths`，并在提示词里写明它只作视觉一致性参考。

**参考图**（用户提供时）：填进 `referenceImagePaths`，逐张标注「视觉语言参考」——只借鉴色彩关系、信息层级、卡片结构、线性图标、留白节奏，明确要求原创构图，不复用其中的账号名、水印、标题、段落、数据、标语与品牌元素。

### 6. 逐图复核

1. 是否 3:4、主体没贴边或被裁（位图尺寸用 `image_info` 核对）
2. 主标题是否一眼读完，紫 / 绿强调是否只落在关键词
3. 中文是否逐字正确，数字与英文是否准确
4. 卡片、线性图标、流程关系是否与本页内容一致
5. 是否出现参考图的账号名、Logo、水印或近似复制
6. 是否与前页保持同一色板、圆角、线宽、阴影与留白节奏
7. **缩到信息流尺寸后主标题与主结构是否仍清楚**
8. 内页标题是否明显小于封面，正文是否占页面主要空间
9. 每个模块是否有完整说明且能在用户原文找到依据
10. 是否滥用「不是…而是…」「能…不等于…」句式

机器检查（比例 / 尺寸）过了仍要**肉眼查文字**——生图错字是这套路线的最大风险。

### 7. 修正（一次只修一个问题）

- 错字：「仅把 X 改成 Y，其余构图、颜色、图标和文字完全不变」
- 太挤：先缩小内页标题区；正文仍挤就拆页，**不把模块说明压成小字**
- 太空：从原文补回字段、步骤、输出、验收，不加空泛口号与装饰
- 文案跑偏：回到「原文依据 → 页面文案」映射替换
- 风格跑偏：重贴完整 Style Lock，并以已通过的那张为视觉一致性参考
- 比例不对：优先重新生成；画面安全时可居中裁成 3:4
- 编辑既有图时只把必要的那张作为参考图，不要把整组都塞进去

**同一张图连续两次仍有中文错误**：① 先把文字压短再生成一次；② 用户要求 100% 精确 → 说明位图限制并转 `xhs-cards` 做文字确定版；③ **不把有明显错字的图当完成稿交付**。

### 8. 保存与交付

- 定稿存到沙盒 `outputs/images/`（`image_generate` 缺省路径）或按用户要求指定路径；命名 `01-cover.png`、`02-overview.png`…，已存在同名就用 `-v2`，**不覆盖**
- 交付列出：每张图片路径、实际页数与采用的视觉系统、最终提示词档（如需复现）

## 固定视觉系统

- 画布外边距 7%-9%，四边留呼吸；背景 `#FCFBFF` / `#FAFAFD` / 纯白，可带极轻薰衣草柔光；不用纸张纹理、噪点、暗角、大面积高饱和底色
- 色板：墨黑 `#181A24`（标题正文）、科技紫 `#6C35E8`（编号 / 线条 / 重点词）、电光蓝 `#4563F2`（过渡）、青柠绿 `#A4E927`（结果 / 通过 / 关键动作）；辅助浅薰衣草 `#F1ECFF`、浅蓝 `#EEF3FF`、浅青绿 `#F1F9E8`、浅橙 `#FFF0E7`（仅警告与次要强调）、细线 `#DED9EF`
- 配比约 72% 白 / 浅底 + 18% 黑字线 + 10% 彩色强调；单页最多 3 个强调色，紫绿为主；渐变只用于 1-2 个关键词或小图标
- 字体：现代中文无衬线（粗体系统黑体气质），不用手写体 / 书法体 / 衬线体；模块正文 12-28 字完整句；数字编号用白字紫圆点或紫数字配细线
- 视觉占比：封面标题占页面高 14%-23%；内页标题区 8%-14%；内页主内容区 58%-72%；页脚结论区 8%-16%
- 组件：白底大圆角卡 + 轻柔紫灰阴影（不用重黑阴影，嵌套不超过两层）；细线圆角端点线性图标（浏览器窗口 / 代码 / 流程 / 清单 / 文档 / 目标 / 盾牌 / 机器人 / 用户 / 权限 / 图表），紫描边为主、完成态青柠绿、橙色只表风险；流程一条最多 5 个主节点（超过拆页）；装饰低对比、只放角落与空白区
- 密度：一页一个中心结论；内页 4-6 个模块；文字占画面 38%-48%；卡片覆盖 65%-76%；信息多就加页，不压字号

固定负向约束（一并写进提示词）：

```text
Do not copy any reference image layout. No copied creator name, no logo, no watermark, no signature, no fake interface screenshot, no garbled text, no invented Chinese characters, no long paragraphs, no tiny dense type, no photorealism, no glossy 3D mascot, no scrapbook collage, no childish stickers, no heavy black shadows, no dark full-bleed background, and no excessive decoration.
```

## 排版禁区

连续 3 页同一种卡片矩阵；每页同时出现顶部标签 + 页码 + 章节名 + 账号名 + 英文口号；一页超过 6 个平级重点；用大量装饰弥补内容不足；细小正文塞满卡片；大标题大图标挤掉正文只剩名词标签；把原文改写成口号；把封面做成目录或最后一页变成空泛鸡汤。

## 原创与安全

- 参考图只给视觉方向：不复制其标题、文案、账号名、Logo、水印、独特插图或逐像素布局；不冒充其他创作者
- 不生成虚假数据、收益承诺、排名、疗效或未经提供的事实
- 不用「某位在世设计师 / 艺术家的风格」描述，只用客观视觉特征
- 未经用户要求不生成真人肖像或品牌商标
