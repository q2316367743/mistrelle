# 小红书图文卡片（画布版）

把用户内容变成一组可发布的小红书图文，而不是只做一张封面。

**交付形态：N 个画布文档**——`canvas_create` 一页一个画布（1080×1440，3:4），页序在右侧画板的下拉里按版本号排列；需要成品图时逐页 `canvas_export` 导出 PNG。为什么不用 HTML：本项目的图一律走画布画板，页内元素可拖动、可改属性、可直接导 PSD，用户能在画板上继续改。

（需要**位图风格**的信息图 / 组图（模型直出、不可编辑文字）走 `xhs-image`；只要封面走 `xhs-cover`。）

## 核心交付

- **一组 6 张以上**，常规 6 / 7 / 8 / 9 四档，复杂内容可由用户指定更多
- 第 1 张负责点击；第 2 张负责留人；中间页负责兑现；最后 1 张负责总结 / 验收 / 收藏
- 全组共用一套调色板与组件语言（`canvas_set_palette` 锁定 token），但每页版式随内容变化
- 账号名只在首页出现；内页不重复品牌名、章节名、英文口号
- 未要求不要导出 PNG；先说清页数与结构再动手

## 开工前必须确认的两项

用户已明确风格与页数就直接执行；否则在同一条消息里给出候选：

**1. 风格**：先 `canvas_guidelines("styles")` 读画布风格库，按赛道选 3-5 个候选 + 1 个「智能匹配」，每个候选一句话说明适配理由（如「留白克制，适合教程 / 知识型」「深色科技感，适合 AI / 工具」「暖调编辑感，适合经验分享」）。用户选「智能匹配」或说「你定」时，先告知选中的风格与理由再制作。风格只决定颜色、字体气质、圆角、线条与装饰母题，**不改变内容逻辑**，不得为了像某风格牺牲中文可读性。

**2. 页数**：A 6 张（精简：结论少、步骤短）/ B 7 张（标准：一个完整方法或清单）/ C 8 张（实操：含样例、模板、验收，**默认优先推荐**）/ D 9 张（深入：完整 SOP 或多步骤教程）。结合原文给一个推荐档位与一句理由。未经用户选择，不要擅自把长内容硬塞进 6 张。

## 内容拆解

先读完整内容，再建页面结构。不要边读边排。提取：目标读者（谁会因为这组图停下来）、核心承诺（看完能完成什么具体动作）、最小完整链路（准备 → 操作 → 结果 → 验收）、可直接复用的材料（提示词 / 字段表 / 命令 / 清单 / 模板 / 判断标准）、必须删的内容（重复铺垫、爹味教训、空泛鼓励、同义反复）。

每组至少包含 **3 类「可拿走的东西」**：可复制提示词或话术 / 文件夹结构或字段表 / 操作步骤 / 示例输入与预期输出 / 验收清单 / 常见错误与修正方法。
纯概念内容也要转成动作：概念是什么 → 什么场景用 → 第一步怎么做 → 做完看什么结果。

## 页数与页序

按内容选结构，不机械套模板。

**6 张精简版**：封面 → 核心结论 / 总览 → 第一步 → 第二步 → 示例 / 模板 → 验收 / 总结
**7 张标准版**：封面 → 为什么值得看 / 最终结果 → 准备 → 步骤 1 → 步骤 2 → 示例 / 常见错误 → 验收 / 复用
**8 张实操版（默认）**：封面 → 结果预览 → 输入 / 准备 → 规则 / 口径 → 可复制执行材料 → 小样试跑 → 输出结果 → 验收与复用
**9 张深入版**：在 8 张上增加一张（对照示例 / 失败案例与修正 / 第二个关键步骤 / 进阶配置）

超过 9 张时每增加一页都要有独立价值，不能用空话凑页。

四类内容的页序：
- **教程 / SOP**：封面结果 → 成品预览 → 准备 → 规则 → Step 1 → Step 2 → 输出 → 验收（每步回答：做什么 / 具体怎么做 / 做完看到什么）
- **干货清单**：封面利益点 → 全部条目总览 → 每 1-2 条一页 → 示例 → 收藏清单（条目句式要平行，不要一页全是名词下一页突然写长段故事）
- **方法论**：封面判断 → 旧做法的问题 → 新框架 → 框架各环节 → 案例 → 适用边界 → 复盘（至少要落到一个具体例子，不能只画抽象图）
- **个人经验 / 故事**：封面反差 → 起点 → 问题 → 关键转折 → 做法 → 结果 → 可复制经验 → 结尾（提炼可复制经验，不写「所以大家一定要努力」）

**页面密度**：一页只讲一个主问题；每页正文 70-150 个中文字符（表格 / 清单按视觉占用判断）；封面信息最少；内页可更密但必须留明显留白；先删次要说明再压缩间距，不要把正文缩成难读的小字；相邻两页避免完全相同的卡片阵列。

## 页面组件（画布实现）

同一组内至少用 3 种组件，避免每页都是四宫格。

| 组件 | 适合内容 | 画布实现要点 | 限制 |
|---|---|---|---|
| 大标题 + 一句话 | 封面、转场、结论 | 大字号 text 节点 + 一行副标 | 信息少、留白大 |
| 两栏对照 | Before/After、错误/正确 | 两个 group 左右对称 | 两边句式对称 |
| 三步流程 | 操作链路 | 三组「序号圆 + 标题 + 说明」 | 每步不超过 3 行 |
| 表格 | 字段、样例、验收数据 | rect 斑马纹 + 对齐的 text 列 | ≤6 行、≤6 列 |
| 代码 / 提示词卡 | 可复制材料 | 深底圆角 rect + 等宽字形 text | 保留完整语义，不做假代码 |
| 清单 | 验收、准备、避坑 | 每行「勾选符号 + 一句」 | 每页 4-6 条 |
| 单一大数字 | 结果、阈值、时间 | 一页只突出一个超大 text | 一页一个 |
| 输出文件卡 | 文件名、字段、产物 | 2-4 张并列小卡 | 卡内不堆细节 |
| 时间线 | 故事、流程、计划 | 竖线 + 3-5 个节点 | 节点 3-5 个 |

**页内节奏**：第 1 页留白最大；第 2 页立即给结论或成品（不写背景长文）；中间页信息密度最高但仍只有一个主问题；倒数第 2 页给输出、案例或易错点；最后一页给验收、复用或完整清单。

## 视觉底线（1080×1440）

- 首图标题 88-128px；内页标题 60-76px；正文 36-44px；辅助信息不低于 30px
- 左右安全边距 80-96px；**底部约 18% 被平台标题与头像盖住**，落款与关键信息往上收
- 白底风格用深色正文，深色风格用高对比浅色正文
- 一页强调色不超过 1 个，装饰母题不超过 1 类
- **图上文字全部用画布 text 节点排版**，不要让生图模型画字（中文小字必糊）
- 字体用 `font_list` 查到的本机真实字体，不要臆造字体名

## 画布工程约束

- **一页一个画布文档**：`canvas_create({ width: 1080, height: 1440, title })`，页名按页序命名：首页 `封面`，其后 `P2 · <该页主题>`、`P3 · …`
- 首页建好后用 `canvas_set_palette` 锁定整组调色板 token（背景 / 主色 / 强调色 / 正文色），后续每页只引用 token，保证整组一致
- 单页铺版用 `canvas_batch_edit`，**每批 ≤15 个操作**，构建顺序：背景 → 主视觉 → 装饰 → 文字；单页节点多时拆多批
- 页面结构用正常的分组与对齐（group + layout），不要靠手算坐标硬堆；坐标不确定时先用 `canvas_inspect` 看真实包围盒
- 每页交付前 `canvas_inspect` 核对：文字有没有溢出、有没有压到底部 18% 安全区、四边留白是否够
- 导出：`canvas_export`（缺省导出当前页 PNG，尺寸 = 画布尺寸）；按用户要求逐页导出，或指定 `path` 存到文章 assets 目录
- 输出中不得残留占位文字、TODO、示例账号或未替换字段

## 工作流

1. 取用户内容（本地文件 / 链接先完整读取，表格数据用 `file_read_xlsx`）
2. 判断内容类型、受众、核心承诺与可实操材料
3. 风格或页数未明确时，给出「3-5 风格 + 智能匹配」与「6/7/8/9 张」候选并等确认
4. 先写**页级大纲**：每页标题、唯一任务、关键材料；检查是否循序渐进（第 2 页不复述封面）
5. 首页 `canvas_create` → 铺版 → `canvas_set_palette` 定调；随后逐页 `canvas_create` + `canvas_batch_edit`
6. 每页 `canvas_inspect` 校验，发现问题当场改（改前先 `canvas_open` 切到该页）
7. 抽查全组：尺寸一致、留白一致、字号层级一致、无重复元素、节奏有变化
8. 交付时说明页数、风格、每页主题与画布版本号；用户要成品图时逐页导出并告知路径

## 质量闸门

全部满足才交付：

- 页数与用户选择一致，且不少于 6
- 每页画布都是 1080×1440
- 无文字溢出、无压安全区（`canvas_inspect` 核对过）
- 第 1 张缩略图能读懂主题；第 2 张没有复述封面
- 中间页至少包含 3 类可操作材料
- 最后一页给验收 / 复用 / 总结，不写空泛关注口号
- 账号名只在首页出现（除非用户另有要求）
- 标题、正文、字段、数字无错字与前后冲突
- 全组共用一套调色板与组件语言

## 实操性检查

交付前自问：用户能否照着某一页直接操作？有没有可复制的文字 / 字段 / 模板？说明了输入与输出吗？给了至少一个具体例子吗？告诉用户怎么判断结果正确吗？
**两个以上答「否」→ 先补内容，不要继续美化排版。**

## 边界

- 用户只给主题、内容不足时，先补内容骨架或请求原文，不用空话凑够 6 页
- 需要插画、实拍或复杂场景图时：走 `xhs-image` 生成位图素材，再作为 image 节点填进画布
- 医疗、法律、金融收益类内容不制作确定性承诺
- 不使用他人 Logo、商标或未授权素材冒充官方视觉
