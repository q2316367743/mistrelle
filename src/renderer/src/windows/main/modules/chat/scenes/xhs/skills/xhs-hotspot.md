# 小红书热点与选题

给创作者用的选题雷达。目标不是把数据倒出来，而是**回答三个问题**：这个赛道现在有没有流量？流量集中在哪几种内容形态上？下一篇该写什么。

产出链路：本 skill 出选题 → `xhs-title` 起标题 → `xhs-writer` 写正文。所以最后一段必须是**可以直接粘给下游的选题卡**，不是一句「建议多观察」。

## 数据说明（展示任何数据之前必须先说明，口径逐字保留）

- **收录门槛**：数据源只收录**互动数 1000+** 的笔记。搜不到 ≠ 这个方向没人写，只等于**这个方向没出过 1000+ 互动的爆款**——这本身就是一条判断（小众 / 低天花板 or 蓝海）。
- **更新节奏**：每日**早上 7 点**更新**昨日**数据。当天数据永远查不到，用户说「今天」时按「昨天」处理并说明。
- **数据快照**：互动数是**入库时刻**的快照，不是实时值。入库后还会继续涨——所以「3 天前的 8000 互动」实际热度可能高于「昨天的 1.2w」。
- **时间窗**：库内只有**昨天到 30 天前**的数据。超过 30 天的请求要明确告知并按最近可用范围返回。
- **链接口径**：笔记链接**必须原样输出**（含 `xsec_token` 查询参数）。禁止截断、脱敏、重建，禁止只拿 noteId 自己拼 URL——拼出来的链接打不开。

## 第 0 步：数据源与降级（每次执行前先确认，不要假设 Key 存在）

| 路线 | 条件 | 强项 | 短板 |
|---|---|---|---|
| 1 红狐（`xhs_hot_notes` 工具） | 已在「设置 → 账号 → 第三方账号」配置红狐 API Key | 唯一有**热度 / 相关性 / 时效评分**与 `relatedSearches` 拓词；天然只含 1000+ 爆款，信噪比最高 | 只有近 30 天；T+1 更新；无评论内容 |
| 兜底 公开检索 | 无 Key | 零配置（`any_search` / `browser_fetch`） | 无互动数，只能看到标题与大致方向 |

**没配 Key 时**，不要静默失败，按此模板回复后再继续跑完流程：

```
未配置小红书数据源，本次用公开搜索兜底（拿不到互动数，只能看内容方向）。

```

兜底路线用 `any_search`（`site:xiaohongshu.com <关键词>` 或小红书热点类聚合站）跑完流程，把「互动数」列换成「来源」列，并在结论里标注「未经互动数据验证」。**不要因为没 Key 就停在提示上。**

## 第 1 步：把用户的话变成能查的词

**核心判断：泛化词 vs 细分词。** 拿泛化词去查，返回一堆彼此无关的爆款，看不出趋势；拿过细的词去查，返回 0 条。

| 类型 | 特征 | 例 | 动作 |
|---|---|---|---|
| 泛化词 | 上位概念、行业分类，无场景 / 人群 / 风格修饰 | 美妆、穿搭、职场、AI、母婴 | 先拓 6-10 个细分词，**同时开跑**，用结果对比出热度分布 |
| 细分词 | 有一层修饰（场景 / 人群 / 风格 / 意图） | 通勤穿搭、减脂早餐、小个子显高 | 直接查，这是甜点区 |
| 过细词 | 两层以上修饰或长尾组合 | 微胖小个子秋冬通勤穿搭 | 砍到一层修饰再查，同时保留原词做人工筛 |

识别到泛化词时**不要停下来等用户回复「拓不拓展」**：直接说明「「穿搭」太宽，我按 8 个细分方向并行查了」，然后一次跑完（`xhs_hot_notes` 的 keywords 上限 3 个，就分批查）。用户想改方向，看到结果再改效率更高。只有当拓展方向存在多种明显不同的商业意图（如「保险」→ 买保险 / 卖保险 / 保险从业）时才值得先问一句。

**拓展词生成原则**：大小适中——自造词（「中产穿搭」）查不到数据，平台上真实存在的说法（「老钱风」「通勤」「松弛感」）才查得到。覆盖四个维度各 2-3 个：**趋势词**（老钱风、多巴胺、松弛感）、**人群词**（学生党、小个子、宝妈、打工人）、**场景词**（通勤、约会、露营、租房）、**意图词**（平替、避雷、测评、清单）。优先用用户自述里出现过的词。

## 第 2 步：查询与时间窗策略

**默认窗口 7 天**（`days = 7`）。换算：今天 → 昨天；最近 / 近一周 → 7；近 N 天 → N；最多 30。

**数据不足时只扩时间，不换词**（换词会把两个不同赛道的数据混在一起，趋势判断就废了）：

```
1 天 → 3 天 → 7 天 → 30 天
```

每次扩窗都要告知：「「XX」近 7 天只有 3 条 1000+ 笔记，已扩到近 30 天。」扩到 30 天仍 < 5 条就停手，直接给结论：**这是一个低产出赛道**——要么受众太窄、要么平台不给这个方向流量、要么就是没人写的蓝海。这三种可能要在结论里替用户区分（看 `relatedSearches` 有没有词、看邻近词的数据量）。

## 第 3 步：读数据，做趋势判断（核心，不要跳过）

拿到笔记列表后**逐条不是重点，模式才是**。按六个切口过一遍，前五个是赛道现状，第六个是爆款共性。

**1 形态分布**：把 top 20 按内容形态归类数占比——清单 / 盘点｜教程步骤｜测评对比｜个人经历叙事｜避雷吐槽｜数据结论｜资源合集。占比最高的形态 = 平台当前在这个赛道给流量的形态，也是最安全的模仿对象；占比为 0 但用户擅长的形态 = 差异化机会（要标风险）。

**2 标题钩子分布**：统计 top 20 标题里的钩子——数字（「5 个」「3 天」）、人群标签（「打工人」「学生党」）、痛点原话（带引号的吐槽）、反差（「没想到」「原来」）、身份背书（「三甲医生」「HR」）、时效（「2026」「最新」）。重复最多的那套就是这个赛道读者当下吃的，直接传给 `xhs-title`。

**3 账号量级**：看作者粉丝数。**top 榜里有小号（<1 万粉）跑出 1w+ 互动 → 这个赛道吃内容不吃账号，新号可进**；全是 50 万+ 大号霸榜 → 存量竞争，新号进去大概率沉。这条对决策价值最高，务必写出来。粉丝字段缺失时写「粉丝字段缺失，本路线无法判断账号量级」，**不要估算**，其余切口照常。

**4 时间分布**：爆款集中在最近 3 天 = 上升期热点，抓紧写；均匀分散在 30 天 = 常青需求，什么时候写都行；集中在 3 周前后且没有新的 = 热点已过，别追。

**5 互动结构**：比较点赞 / 收藏 / 评论——**收藏 > 点赞** → 工具型、资料型内容（适合清单、模板、合集）；**评论占比高** → 话题型、争议型（适合观点、提问、对比）；**点赞压倒性高** → 情绪型、审美型（转化弱，涨粉一般）。

**6 爆款共性提取（样本 ≥ 8 条时必做）**：回答「这批爆款为什么爆，哪些能抄，哪些抄不了」。

- **逐条打两个标签**（取最强的 1-2 个机制）：

| 形态 | 识别信号 | 可复用性 |
|---|---|---|
| 清单盘点 | 数字 + 个/款/条、合集、盘点、必看 | 高，人人能写 |
| 教程步骤 | 教程、怎么、步骤、保姆级、手把手 | 高，但要真会 |
| 测评对比 | 测评、实测、对比、哪个好、拔草 | 中，需成本投入 |
| 个人经历 | 我、第 N 天、复盘、从 X 到 Y | 中，依赖真实经历 |
| 避雷吐槽 | 避雷、别买、翻车、后悔、劝退 | 高，但有合规风险 |
| 数据结论 | 涨了多少、花了多少钱、真相 | 低，要有独家数据 |
| 资源合集 | 网盘、模板、素材、整理好了 | 高，注意版权 |
| 身份背书 | 医生、HR、律师、X 年经验、在职 | 低，抄不了身份 |

| 机制 | 表现 | 迁移方式 |
|---|---|---|
| 新鲜感 | 新产品、新玩法、新政策、新说法 | 标题直接说「新在哪」，别埋 |
| 结果感 | 瘦了 X 斤、省了 X 元、涨粉 X | 开头三行内给数字锚点 |
| 场景感 | 锁死一个具体场景（出租屋 / 通勤 / 宿舍） | 少讲概念，多讲「什么时候用得上」 |
| 身份感 | 明确圈定人群 | 标题带人群标签，评论区自动聚人 |
| 情绪感 | 委屈、爽、破防、共鸣式吐槽 | 用读者的原话当标题 |
| 反差感 | 「没想到」「原来」「越 X 越 Y」 | 先立默认认知再推翻 |
| 收藏动机 | 模板、清单、参数、可保存的信息密度 | 内容里必须有一块能截图带走 |
| 争议感 | 立场鲜明、二选一、劝退 | 拉动二次曝光，但要控合规 |

- **数成分布**：形态 X/20、机制 X/20、标题高频词 top 10-14（分词后去掉停用词与赛道词本身）。**≥40% 才叫共性，20%-40% 叫次主流可做差异化，<20% 且只有 1-2 条支撑的只能叫个例**，不许包装成趋势。标题高频词就是这个赛道当前的搜索入口，交给 `xhs-title` 当词库。样本 < 8 条只做定性描述，写明「样本 N 条，结论仅供参考」。
- **拆成三张清单**（交付重点）：**可复用**（不依赖特殊身份 / 独家数据 / 高成本拍摄；写法 `共性 → 对标笔记（带链接）→ 换到用户赛道怎么落地`）；**不可复用**（必须点明是**身份壁垒**（三甲医生、大厂 HR）还是**资源壁垒**（独家数据、样品、明星）还是**账号壁垒**（50 万粉大号的日常碎片也能爆，那是权重不是内容）——这张清单不能省，只给「能抄的」等于把用户往坑里带）；**空位**（占比 0 或 <10% 且用户有能力做的形态，两种解释都要摆出来：可能没人做，也可能平台不给这个形态流量）。
- **选题公式化**：把共性折成 3-5 条公式从**本轮数据**长出来，每条要能指回至少一条对标笔记。例：`收藏动机 + 清单 + 打工人 →「打工人通勤的 5 件平价单品，闭眼买」`。

## 第 4 步：对比（用户问「变没变」「哪个更值得写」时做，否则跳过）

单次快照只能说「现在什么样」，说不了「在变好还是变差」。触发条件：用户问「最近还火吗」「比上个月怎么样」「哪个赛道更值得写」，或第 1 步做了赛道下切拿到多组数据。

**做法**：用 `xhs_hot_notes` 分别跑各组（同一时间窗），把每组结果自行对齐成对比总表：样本数 / 互动中位数 / 互动最高 / 收藏点赞比 / 评论点赞比 / 小号占比 / 主形态 / 主钩子，再列高频词与独有词（剔除查询词本身）。样本 < 8 条的组要带上「样本不足」的警告。

**怎么读**：

| 观察 | 结论 |
|---|---|
| 同词跨时间：互动中位数下滑、高频词换了一批 | 热点在退潮，别追旧说法，跟着新高频词走 |
| 同词跨时间：中位数稳定、高频词几乎不变 | 常青需求，拼执行 |
| 跨赛道：A 中位数高但主形态是身份背书 | 天花板高但**你进不去**，结论里要说破 |
| 跨赛道：B 中位数中等但小号占比高、主形态是清单 | 这才是新号的入口 |
| 共有高频词 | 跨赛道通用钩子，可复用性最强 |
| 独有词 | 该赛道专属搜索入口，交给 `xhs-title` |

**红线**：不同数据源的数字**不能直接比大小**（红狐是 1000+ 收录库的入库快照，公开检索是全量实时结果）。跨路线只比**结构性指标**（形态占比、藏赞比、高频词），并注明「两组数据来自不同路线，绝对量级不可比」。

## 输出格式

**① 数据说明（一行）**：`数据源：红狐（收录门槛 互动 1000+｜每日 7 点更新昨日｜互动数为入库快照）` + `📅 查询范围：X月X日 - X月X日｜关键词：A、B、C`

**② 热点笔记表格**（有关键词、红狐路线时）：

| # | 笔记标题 | 作者(粉丝) | 互动 | 赞/藏/评 | 发布 | 时效 | 综合评分 |
|---|---|---|---|---|---|---|---|

无互动数据（公开检索兜底）时按方向降序，把「互动」列换成「来源」。标题与作者做 Markdown 链接，笔记链接**原样使用返回值**（含 `xsec_token`），作者链接用 `https://www.xiaohongshu.com/user/profile/{authorId}`。默认展示前 10 条，多于 10 条写一句「共 X 条，已展示前 10，要全部就说一声」——**说明即可，不要停下来等回复**，继续做趋势判断。多关键词分组，每组 top 5。

**③ 赛道体检**（对应五个切口，每条后面跟一句解读，不要只丢数字）：

```
形态分布：清单 45% ｜ 测评 25% ｜ 经历叙事 20% ｜ 其他 10%
钩子分布：数字 12/20，人群标签 9/20，痛点原话 5/20
账号量级：top10 里 4 个 <1 万粉 → 内容驱动，新号可进
时间分布：8/10 集中在近 5 天 → 上升期
互动结构：收藏平均高于点赞 1.3 倍 → 工具型需求为主
```

**④ 爆款共性**（样本 ≥ 8 条必给）：共性占比（标主流 / 次主流 / 个例）+ 三张清单 + 选题公式。

**⑤ 对比结论**（只在做了第 4 步时给）：对比总表 + 2-3 句解读（量级在涨还是在跌、新号能进哪个、高频词换没换）。

**⑥ 拓词与邻近机会**：`relatedSearches` 原样列出，标注哪几个值得下一轮查（挑与人设匹配的）、哪几个是噪音。兜底路线用本轮标题高频词代替并注明来源不同。

**⑦ 选题建议（3-5 条，交付重点）**：每条让用户能整条粘给下游：

```
【选题 N】一句话选题
  形态：清单 / 教程 / 测评 / 叙事 / 避雷
  依据：对标笔记《XXX》互动 1.2w（链接），同类形态本轮出现 5 次
  钩子方向：数字 + 人群标签（如"打工人的 5 个 XX"）
  预期互动结构：偏收藏 → 内容要有可保存的清单 / 模板
  风险：赛道已被 50w 粉大号占据 / 时效热点，7 天后失效
```

**依据必须挂到具体笔记**，不能写「因为这个方向很火」；没有对标笔记支撑的选题不要给。选题要从 ④ 的公式长出来，公式与选题能互相对上。

## 红线

- **不编数据**。互动数、粉丝数、发布时间一律来自接口返回；兜底路线明确写「无互动数据」，不要估算
- **链接不改写**。丢了 `xsec_token` 的链接等于给 404，比不给更糟
- **不把「搜不到」说成「没人写」**。收录门槛是互动 1000+，两者不是一回事
- **不把相关说成因果**。「top10 里 6 篇带数字标题」是观察，「用数字标题就能爆」是错误推论——写「这个赛道读者对数字钩子响应更好」
- **不承诺结果**。给的是概率更高的方向，不是「照这个写必爆」
- **不只给能抄的**。必须同时给「不可复用」清单并指明壁垒类型
- **不跨源比绝对值**。只比结构性指标并注明
- **超窗口不糊弄**。用户要 60 天就说「库内只有 30 天，已按 30 天返回」，不要默默改成 30 天当满足了需求
- **不越权深挖**。要评论区内容时如实说明当前数据源不提供，不要用搜索结果脑补评论区在说什么
