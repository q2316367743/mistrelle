# 公众号爆款数据分析

用 `gzh_trends` 工具查公众号爆款数据（四榜 / 赛道两种模式），再按本 skill 解读。数据为热榜快照，非指定账号全量历史。

## 泛化词闸门（强制）

「职场」「情感」「AI」「健康」这类 **大类词禁止直接调工具**——数据会散掉没有参考价值。

遇到大类词必须：

1. 先输出 10 个细分赛道词（如「职场」→ 体制内写材料、大厂裁员、35 岁转行、副业搞钱……）
2. 等用户回复选哪个（或说「拓展 / 不拓展」）
3. **同一轮回复内禁止调 gzh_trends**

用户给的词已经足够细分（如「大厂裁员」「宠物殡葬」）才可以直接查。

## 默认赛道组（用户没给具体赛道时用）

用户只说「扫一遍 AI / 科技赛道」而没给具体赛道时，按下面六组传 `sector` 模式，不要臆造：

| 赛道 | 关键词 |
|---|---|
| AI Agent | AI Agent, Agent框架, 智能体 |
| Skill | skill, Skills, AI Skill |
| Claude Code / Codex | Claude Code, Codex, AI编程 |
| AI知识管理 | AI知识管理, 知识库, 个人知识管理 |
| AI写作与内容生产 | AI写作, 内容生产, 自媒体AI |
| 企业AI落地 | 企业AI, AI落地, 数字员工 |

用户所属领域不在表内时，先给细分赛道推荐（同泛化词闸门流程）再按确认结果构造。

## 工具用法

`gzh_trends(mode, keywords, days?)`：

- `mode: 'keyword'`：按关键词查四榜——低粉高阅读 / 阅读靠前（10w+）/ 数据增长中（1w–10w）/ 原创靠前；适合「看看这个赛道最近什么在爆」
- `mode: 'sector'`：赛道日报，`keywords` 传多组「赛道名:词1,词2」，聚合多词对比；适合「帮我把这几个赛道都扫一遍」
- `days`：回看天数（默认 7，数据稀疏时加大； **最多 30 天**）

固定边界话术（数据为空 / 更新延迟时原文使用）：

- 「今天的数据暂未更新，先看最近几天的。」
- 「当前仅支持最近 30 天的数据，已按 30 天返回。」

## 多赛道横向对比（sector 模式进阶）

用户给了多个赛道或用了默认赛道组时，一次 sector 调用传全部赛道组，然后做横向对比：

1. 每个赛道各取最高阅读与最高分享文章，列成对比表（赛道 | 最高阅读 | 最高分享 | 爆款标题）
2. 指出当下数据整体更强 / 增长更明显的赛道，说明依据（阅读水位、互动构成）
3. 结论落在「**下一篇写哪个赛道、从哪个角度切入**」，可结合用户已写过的主题给错位建议
4. 单赛道数据稀疏时如实说明，不硬比

## 解读协议（工具返回数据后必做）

1. **爆款识别**：指出最高阅读与最高分享的文章，说明它们分别在哪个榜、数据构成
2. **共性提炼**：这些爆款在选题角度、写作风格、结构上的共同点（3–5 条）
3. **标题公式**：从样本标题反推可复用的标题模式（如「数字 + 反差」）
4. **写作参考**：给出 2–3 条可直接执行的选题 / 角度建议
5. **对标线索**：低粉高阅读条目 = 标题与结构参考；同一账号反复上榜 = 值得持续跟踪的对标对象
6. 数据只有快照，解读时明确「近 N 天」，不要说成「长期规律」

## 输出约定

- 用 Markdown 表格展示文章清单（标题 | 账号 | 阅读 | 数据构成），最多 10 条
- 结论落在「用户下一篇该写什么」上，不给空洞的行业综述
- 需要深挖某篇时，建议用户贴链接或标题，走聊天继续分析
